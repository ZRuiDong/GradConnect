# 代码审查与部署结论（2026-11-18）

已完成一轮覆盖现有业务代码、模板、交互脚本、迁移与部署配置的检查，并修复能够确认和复现的问题。此次没有新增数据迁移，没有修改工作区现有账号、业务记录或上传文件。结果不代表不存在未发现的问题，也不代替真实 PostgreSQL、Nginx 与公网负载验收。

## 修复与优化

| 范围 | 发现的问题 | 处理结果 |
| --- | --- | --- |
| 毕业、履职 Excel 导入 | 部分有效 XLSX 没有工作表范围标记，会被拒绝；范围标记偏小时可能漏读后续行 | 按实际单元格流读取，补齐可选空列，保持 2000 行、列数、文件体积及解压体积上限；加入缺失/错误范围和超限回归 |
| 履职名单解析 | 读取所有学生及履职历史；无关学生的异常历史可能阻止本次名单 | 仅查询本次名单涉及的学生及履职，仍校验目标学生及预览冲突 |
| 三类导入确认 | 页面读取预览后，另一请求取消预览或定时任务清理它，服务可能报 500 | 学生账号、打卡、毕业/履职名单统一返回“预览已取消或被清理”，回到列表，不写业务数据 |
| 月度打卡报表 | 每 500 行重复查询学生当前职务，同一学生跨月重复加载；读取无用账号字段 | 当前职务一次查询、详情只读取所需字段；导出内使用有数量上限的文字高度缓存，保留样式与内容 |
| PostgreSQL 连接 | URL 中 TLS 等参数此前被忽略；空主机的 Unix socket URL 在备份环境中可能异常 | 显式校验并传递四类受支持参数，默认连接超时 5 秒，连接复用 60 秒且启用健康检查；备份同步 TLS/超时选项，密码不进入命令行 |
| Nginx 上传 | 所有入口均允许 512 MB 请求 | 普通入口 32 MB，仅账号导入、视频、多附件业务设置相应上限；公共代理头独立为 `deploy/proxy_common.conf`，避免入口间配置漂移 |
| HTTP 验证脚本 | 用字符串 `page=` 判断分页参数，会把 `per_page=` 误判为未清除页码 | 改为解析查询参数并检查独立的 `page` 键 |
| 部署说明 | 仍以 PostgreSQL 14 为起点，未清楚说明 OSS 适配及完整媒体备份增长 | 改为维护中的 16/17，说明本地私有文件的现成部署方案、OSS 改造边界、带宽、异地留存与实际环境验收 |

数据库 URL 目前支持 `sslmode`、`sslrootcert`、`connect_timeout`、`application_name`；未知、空值或重复参数会主动报配置错误，避免参数被静默丢弃。

## 部署建议

先采用一台 Linux LTS 主机，建议 4 核 / 8 GB、至少 100 GB SSD；保持 Nginx → Gunicorn → Django → PostgreSQL 16/17，并使用现有数据库 Session。2 核 / 4 GB 可作试运行起点，正式容量由混合压测决定。1500 是账号规模，须另行确认高峰并发及视频观看量。

当前版本直接使用私有持久化媒体目录与 Nginx X-Accel-Redirect。视频增加后可接入私有 OSS，但需要上传、鉴权下载/签名地址、Range、备份和历史文件迁移适配；当前没有实现仅改配置即可切换。视频网络需单独估算，例如 20 路各 2 Mbps 约占 40 Mbps。

正式库从空库迁移、创建唯一超级管理员并导入真实学生，勿复制开发测试库。部署到目标服务器后完成 PostgreSQL 全量回归及并发冲突检查、`nginx -t`、HTTPS、私有附件/视频与跨用户权限验收；在导入和导出同时发生时测页面响应，再决定是否增加进程、拆数据库或引入队列。完整备份异地保存并演练恢复，媒体量较大时另行规划增量备份，当前备份命令不会自动清理旧包。

逐步操作、环境变量、服务、上传限制、备份、验收与更新流程见 [部署文档](DEPLOYMENT.md)。后续已将项目纳入 Git 版本管理；每次发布仍应保留源码版本、依赖清单和可恢复备份，实际数据库和上传文件单独备份。
