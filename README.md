# GradConnect

面向研究生与管理员的轻量事务服务 Web 应用。采用 Django 5.2 LTS、服务端模板、数据库 Session，无需 Node 或前端构建。Mac 本地使用 SQLite，正式环境使用 PostgreSQL、Gunicorn 和 Nginx。

代码仓库：[ZRuiDong/GradConnect](https://github.com/ZRuiDong/GradConnect)。仓库包含源码、数据库迁移、导入模板、合成测试素材及部署文档；本地数据库、上传文件、备份、截图、虚拟环境和密钥配置不入库。首次克隆后须重新安装环境并初始化数据库，已有业务数据需单独备份、迁移。

2026-11-18 已完成代码审查与优化，400项测试、65项隔离真实HTTP检查通过。修复Excel名单兼容性和导入取消竞争异常，月度报表SQL由80次降至7次，补齐云数据库TLS参数与备份配置。详见 [审查报告](docs/CODE_REVIEW_20261118.md)；正式部署按 [部署说明](docs/DEPLOYMENT.md) 执行，Nginx主配置须和新增 `deploy/proxy_common.conf` 一起部署。本轮没有新增数据库迁移。

## Mac 本地启动

2026-11-18 后续已补齐站内消息、强制修改临时密码和申请纠错，最新全量回归为 **430项**。这次需要应用 `0015_inbox_password_registration_corrections`；本地已备份并升级，原有账号、密码和业务记录保留。

需要 Python 3.12 / 3.13 / 3.14。macOS 自带的 Python 3.9 不符合本项目依赖要求。

```sh
cd GradConnect
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

访问 http://127.0.0.1:8000/ 。已完成本地初始化的工作区可直接执行最后一条命令（或 `.venv/bin/python manage.py runserver`）；首次克隆的项目需按以上步骤安装依赖、迁移并初始化演示数据。

## 消息、首次改密与申请纠错

- 右上角“消息”进入消息中心，红色数字表示本人未读数量。咨询新建、追问/补充、请假/实习/租房提交及撤回提醒启用中的管理员；管理员回复咨询、审核申请及确认销假提醒对应学生。每名管理员分别记录已读，其他管理员查看不影响本人未读。可按类别、未读/已读/全部筛选，支持分页和全部标为已读。
- 点击消息“查看详情”会跳转至对应事项并标记该条及更早的同事项消息为已读；直接打开业务详情时，前台页面也会通过带CSRF的POST确认该事项已显示的消息。晚于页面打开的新消息保留未读。可见页面每60秒刷新未读数量，后台标签页暂停；消息计数轮询不记录为学生主动活跃。无JavaScript时仍可从消息中心查看并标记已读。升级前历史不补造未读记录，原待办仍可在首页和业务列表查看。
- 单个新建、CSV新增学生、创建管理员及命令行创建超级管理员后，首次登录须先修改临时密码；管理员在业务界面、原生后台或命令行重置密码后也须先改密。填写当前登录密码作为旧密码，新密码须通过强度校验且不能与当前密码相同。强制改密期间业务页面、文件及POST操作均受限制，仍可退出登录；本人改密后当前会话保留，其他会话失效。
- 本次迁移只为从未登录且密码可用的历史账号开启首次改密要求；已登录的历史账号不统一强制改密。不会替换原密码；批量补充学生资料也不会改变密码或强制改密状态。学生管理详情显示是否需要修改临时密码。`portal`须位于`INSTALLED_APPS`的`django.contrib.auth`之前，以确保项目的账号创建/重置管理命令生效。
- 实习与租房的待审核申请新增“撤回并修改”，点击后二次确认；撤回后可修改字段，勾选沿用原附件或上传替换附件，合计至少1份、最多10份，每份20MB。驳回的申请提供“修改并重新提交”，回填原信息和附件。重新提交生成独立待审核申请，原申请、附件及审核意见保留，并可互相跳转；每份原申请只生成一份直接后续申请，重复提交返回已生成的新申请。新申请仍可按同样规则继续撤回、修改、重提。已通过的申请不能撤回或修改，管理员不能审核已撤回的申请。

部署时运行 `migrate`、`collectstatic --noinput` 并重启应用。同步更新Nginx配置，实习/租房的`/<id>/resubmit/`入口也使用256MB的多附件请求体上限。验证见 [功能记录](docs/PRIORITY_FEATURES_VALIDATION.md)。

## 首页、展示顺序与表格排序

原“工作台”已统一改名为“首页”。首页实时显示咨询总量、回复率、待回复咨询、已发布通知、有效规章制度，以及管理员的在校学生数或学生本人的当月打卡总天数；另有待办统计、咨询类别环图、通知类别占比、近六个月咨询趋势和常用入口。管理员查看全平台统计，学生的咨询与申请数据仅来自本人。回复率为“至少收到过一次教师回复的会话数 ÷ 会话总数”，已回复后的追问仍算已获回复；待回复数包含尚未处理的追问。无咨询时回复率显示“—”。

管理员在**通知汇总、办事指南、规章制度、官方问答、学习视频**的每项内容下可使用“置顶 / 上移 / 下移 / 置底”。调序按当前类别、关键词等筛选结果跨页执行，返回内容移动后的页码并定位该项；学生端及首页对应推荐列表同步采用该顺序。未发布、撤下或删除内容不会因此向学生开放，制度仍按有效版本展示。若期间顺序或内容已被其他管理员修改，系统拒绝旧操作并提示重新核对。调整顺序不改变原正文、文件、发布时间或更新时间，并记录操作日志。

学生信息汇总列表使用简洁文字表头，保留列宽拖动、筛选和分页。请销假、实习、租房、干部履职历史、操作记录及各导入/删除核对表的数据列提供上下小三角控制升序/降序。排序在完整结果上执行后再分页，保留原筛选与每页条数；请假导出同步采用所选顺序，导出全部符合条件的记录。勾选、操作按钮和固定账号类型列无需排序。姓名/学号及起止时间在合并列中各有独立排序按钮。月度打卡保留既有六字段排序。履职编辑区也可按职务或日期排序，正在修改记录时须先保存或取消。

办事指南改为蓝色流程目录，突出负责人、办公地点、附件数量和办理流程，与通知卡片清晰区分。咨询详情中学生消息使用绿色右侧气泡，教师/管理员消息使用蓝色左侧气泡，并同时显示头像与身份标签。

本次更新须执行 `python manage.py migrate`（`0011_content_display_order`）、`python manage.py collectstatic --noinput` 并重启应用。迁移为已有内容保留原展示顺序，仅初始化新增排序字段；新发布内容可使用“置顶”提升展示位置。本地数据库已备份并应用迁移，原账号、业务记录和附件引用保留。

## Excel 报表导出

月度打卡和学生信息汇总右上角提供“导出报表”。先应用筛选，再点击导出，文件包含**全部符合条件的记录**，不受当前页码或每页条数限制；打卡排序与列表一致，旧的年月查询链接仍可使用。非法筛选不会悄悄导出全部数据，空结果也生成可查看的空报表。

- **月度打卡报表**：包含“报表汇总”“按月汇总”“月度打卡明细”。明细包括记录姓名/学号与当前姓名/学号、月份、打卡/请假/总天数、班级、党支部、政治面貌、在校及账号状态、当前职务、导入批次和创建/更新时间。管理员导出筛选后的学生记录，学生只能导出本人记录。未导入月份不补零。
- **学生信息报表（仅管理员）**：包含“报表汇总”“学生信息明细”“干部履职历史”。20项明细包括完整身份证号、基本资料、在校/账号/在线状态、全部当前职务、履职条数、最近活跃及登录时间、资料完整性、本月活跃天数/活跃率与内容点击量；历史表逐条列出职务、起止日期、当前有效性及维护时间。默认排除归档学生，如需全部数据应先在“学生范围”中选择包含归档。

Excel中的姓名、学号和身份证等作为文本保存，保留前导零和18位证件号，公式前缀不会作为公式执行；数字、日期保持可排序的原生类型。报表包含导出时间、筛选范围、冻结表头与筛选器，下载操作进入审计。采用逐行写入和分批读取，不新增前端或报表服务依赖。

## 唯一超级管理员与账号管理

系统只允许一个超级管理员。当前本地保留原账号 **`admin`**，其密码不变；旧测试账号 `qa_root` 已调整为普通管理员，密码和历史业务保留，旧登录会话失效。QA生成器以后只生成普通测试管理员，不再建立额外超级管理员。

超级管理员继承全部业务权限，在侧边栏“系统管理 → 管理员管理”中可**创建普通管理员、修改姓名/单位/邮箱、启用/停用、重置密码、强制所有现有会话退出**，并查看账号概况及操作记录。停用、强制退出和重置密码会使旧会话失效；启用后需重新登录。管理员使用停用方式保留历史，不提供管理员硬删除入口。普通管理员不能创建管理员或修改同级账号权限。

唯一超级管理员受保护，不能在页面或模型保存中停用、归档、降权或删除；数据库约束保证不会出现两个超级管理员，并保证超级管理员具有启用状态和业务管理权限。系统账号后台也仅供超级管理员使用，不能从该后台勾选产生第二个超级管理员。

正式空数据库首次执行 `.venv/bin/python manage.py createsuperuser` 创建唯一账号；已有超级管理员时重复创建会拒绝。遗忘超级管理员密码时，在服务器终端执行 `.venv/bin/python manage.py changepassword 现有账号名` 交互恢复，不创建替代超级管理员。更新需应用迁移 `0013_unique_super_admin`，再收集静态资源并重启；迁移优先保留非QA的原超级管理员，其余超级账号调整为普通管理员并保留业务，不在回滚时自动恢复多超级管理员状态。

## 内容点击统计与学生在线活跃情况

通知汇总、规章制度、官方问答、办事指南和学习视频的列表及详情显示**总点击量、本月点击量和今日点击量**。仅统计已登录学生成功打开可访问的内容详情页，学生每次打开详情页均计一次，同一内容在短时间内重复打开或刷新也逐次累计，不再按时间去重；管理员浏览、列表浏览、附件下载/预览、视频分段请求、HEAD和浏览器预取不增加点击量。视频点击表示进入视频详情，不表示完整观看。日期按北京时间划分，本月指当前自然月。首页显示五类内容的本月和今日点击合计及按内容类型的总量/本月/今日分项：管理员查看全体学生，学生仅查看本人。

学生信息汇总的姓名后显示在线圆点，列表与详情每分钟刷新：**绿色**表示最近5分钟有页面访问或可见页面实际交互，**灰色**表示不在线，**红色**表示账号停用、毕业或已归档，红色状态优先。主动退出登录后转为离线，最近活跃时间保留。学生在可见页面的点击、按键和滚动会按分钟节流上报，单纯把页面放在后台不会持续维持在线；在线状态是近期使用情况的近似值，不表示当前一定在阅读。

管理员进入学生基本信息，可选择月份查看最近活跃时间、月活跃率、活跃天数、五类内容点击量和活跃日历。**月活跃率＝该月活跃天数 ÷ 该月已过自然日数 × 100%**，历史月份按整月天数计算，显示保留一位小数。一天内只要成功访问业务页面或在可见页面实际操作，即计一个活跃日。达到60%为高活跃，30%至不足60%为中等活跃，有记录但不足30%为低活跃，0天为暂无活跃。后台在线查询本身不制造学生活跃记录，学生无权查询他人的在线及活跃详情。

统计自本功能启用起累计，旧的访问记录无法补算；升级不会虚构历史点击或活跃天数。旧计数原样保留，逐次累计规则自本次更新起生效，通知点击从接入后开始记录；以前被去重的访问无法还原。按学生/内容/日期聚合保存，不逐条保存导航轨迹或视频播放片段，不使用第三方统计服务。在线时间更新不影响学生资料版本检查。删除有点击或活跃记录的学生时采用归档停用，保留历史统计；开发测试数据清理命令只清理对应测试账号的统计。

通知点击和逐次累计新规则需执行 `python manage.py migrate`（最新为 `0014_notification_click_metrics`）、`python manage.py collectstatic --noinput`，然后重启应用。本地库已备份并升级，已有账号、密码、业务数据及附件引用保持。

## 侧边栏与多人维护

“请销假、实习和租房”“咨询回复”的子菜单支持点击主标题折叠/展开；默认展开当前所在模块。浏览器会分别记住管理员和学生端的分组状态，进入某个子模块时自动展开所属分组。禁用本地存储或 JavaScript 时仍可使用原生折叠菜单，手机端也可展开子菜单。

编辑已有学生资料时，如果其他管理员在期间修改过基本资料、干部履职或账号状态，保存会提示冲突，须重新加载最新资料并核对。本次提交不会覆盖对方的新资料。批量更新预览后如目标基本资料发生变化，会整批拒绝更新；删除核对后如班级、党支部等资料或账号状态变化，也需重新核对名单。更新代码前已打开的旧编辑页面应重新加载，旧的资料更新预览可能需要重新上传。

## 功能

- 登录、退出、修改密码；学生信息汇总支持新增/批量导入及更新学生资料、干部履职历史、组合筛选和核对后删除/归档，保留停用和重置密码。
- 通知汇总：新生入学、党建、招聘信息、评奖评优、竞赛、离校手续、其他七类；管理员发布、替换、撤下与重新发布，学生分类检索、查看正文及 PDF。
- 规章制度按八类查询，类别必选；支持草稿、发布、撤销、历史版本及 PDF 预览/下载，编辑期间原有效版本和分类继续可用。
- 请销假、实习和租房：日常请销假支持导师签字选择、按时间段筛选与管理员 CSV 导出；实习登记、校外租房支持申请附件与通过/驳回审核。
- 咨询回复：官方问答与一对一咨询两个子模块，共用八类筛选；管理员手工整理咨询后预览、确认发布官方问答。
- 学习视频按党建/班团/其他分类上传和检索，管理员可编辑标题、类别和说明；支持 MP4 播放及 HTTP Range，删除后关闭播放入口。
- 月度打卡：每人每月一条汇总，显示打卡天数、请假天数和总天数；支持年份/月/学生筛选，以及月度 CSV 模板、预览和整批更新。
- 办事指南：八类流程检索、负责人/联系方式/办公地址/正文流程、多个 Excel/Word/PDF 附件，管理员发布、替换、撤下和重新发布。
- 关键操作日志、受保护的文件路由、备份及过期数据清理命令。

所有 `is_staff=True` 的管理员具有全平台业务权限；唯一的超级管理员还可管理其他管理员，并使用 `/system/` 的系统账号后台。普通管理员无法进入管理员管理或系统账号管理页面。学生端和业务管理端共用 `/`，登录后按角色显示功能。

## 已确认及默认规则

用户已确认：**只有待审核请假可撤销；打卡改为月度汇总，打卡天数和请假天数只使用整数，总天数为两者之和。**

- 请假：待审核 → 已批准 → 已销假；待审核另可 → 已驳回或已撤销。审核不设多级审批；驳回必须填写意见。获批后的销假由管理员在线确认。
- 学生账号以学号作为登录名，由管理员统一创建，暂不开放自助注册。密码重置线下核验，线上设置新密码。
- 已发布的通知和办事指南面向所有登录学生。原在办事项模块已停用，历史私人咨询仍仅本人和管理员可见。
- 制度正文可直接录入，预览附件统一为 PDF（20 MB 以内）。视频限 MP4（500 MB 以内），推荐 H.264/AAC 编码；程序校验扩展名及文件头，不自动转码。
- 咨询整理为问答时，管理员手工修改、匿名化并确认发布。原始会话不会作为公开问答附带展示。
- 视频采用逻辑删除，制度采用撤销；历史文件保留用于追溯，但访问路由会拒绝无效内容。第一版不提供管理员恢复视频的界面。
- 页面检索覆盖标题、分类及模块正文；不抽取 PDF 内文、不做模糊语义搜索。
- 未实现需求之外的短信、邮件、观看进度、自动打卡、附件病毒扫描和多院系管理员隔离。

## 规章制度与学习视频分类

规章制度类别固定为：**校纪校规、日常事务、教务、评奖评优、竞赛、党建、后勤管理及校园安全、其他**。新增制度时必须从下拉框选择类别；保存为草稿后仍需管理员确认发布。学生可选择“全部类别”或指定类别，并结合标题、摘要或正文关键词检索，翻页保留条件。

制度分类随每个版本保存。编辑草稿改变类别时，学生仍按当前有效版本的类别检索和查看；确认发布后才切换到新类别。管理员列表按当前展示的草稿（无草稿时为有效版，否则最新版本）进行类别及关键词组合筛选，不用历史版本的类别匹配另一个版本的正文。撤销制度不会出现在学生分类结果中，原详情和 PDF 入口仍受发布权限保护。

学习视频类别固定为：**党建、班团、其他**，上传时必须选择。学生可按类别结合标题或内容介绍查询，已删除视频不显示。管理员可在视频详情选择“编辑视频信息”，修改标题、类别和说明，不需要重新上传原 MP4；删除后不能通过编辑恢复或继续播放。

列表选择某类别后点击新增/上传，会带入已选类别；直接进入新增页面时不预选。两类表单拒绝空类别和非固定选项，学生没有上传或编辑权限。分类名称使用有间距且可换行的网格展示，较长的“后勤管理及校园安全”保持完整。

已有数据升级需执行 `python manage.py migrate`（应用 `0009`）、`python manage.py collectstatic --noinput` 并重启。旧分类按明确对应关系转换（如学生管理/综合事务→日常事务、后勤/校园安全→后勤管理及校园安全、班团建设→班团），无法对应的归入“其他”。原分类内部保留以支持回滚；原正文、制度版本、发布状态、视频删除状态和所有文件引用保留。管理员可通过原制度草稿流程或视频信息编辑调整分类。

## 通知汇总

左侧导航“通知汇总”位于“首页”下方，学生和管理员均可进入。类别固定为：**新生入学、党建、招聘信息、评奖评优、竞赛、离校手续、其他**。

管理员选择类别后点击“发布通知”，填写标题、可选摘要和正文，也可上传附件（最多 20 MB）；正文和附件至少有一项。附件支持 Word（doc/docx）、Excel（xls/xlsx）、PDF、图片（jpg/jpeg/png/gif/webp/bmp）、PowerPoint（ppt/pptx）、TXT、CSV 和 ZIP。PDF 和图片可在线查看及下载，其他格式下载后使用相应软件查看。系统按扩展名确定文件类型，不采信浏览器上传的 MIME 类型；上传会检查大小和基础文件格式，Office、文本及压缩包不在网页内执行或转换。发布后学生可立即查看。点击“修改 / 替换通知”可更新标题、类别、正文或附件，已发布通知的修改立即生效。

“撤下通知”会停止学生列表展示、搜索、原详情地址访问及附件下载。管理员仍可查看和修改撤下内容，修改不会自动恢复发布，须点击“重新发布”。系统保留操作记录，附件统一通过鉴权入口提供。通知按管理员设置的展示顺序排列。

学生可结合类别与关键词搜索标题、摘要和正文；不检索附件内文。学生只看到已发布通知，无法进行管理操作。管理员可额外按发布状态筛选。

通知模块初次部署须应用 `0003_notification` 迁移。本轮附件格式扩展无新增数据库结构，已有 PDF 附件继续使用；更新代码后执行 `python manage.py collectstatic --noinput` 并重启应用。

## 办事指南

入口位于“通知汇总”下方，类别为：**日常事务、评奖评优、新生入学、离校手续、党建、后勤、教务、其他**。管理员可发布、修改/替换、撤下及重新发布；学生可按类别筛选，并搜索标题、负责人、联系方式、办公地址或流程正文。

每份指南填写标题、类别、**负责人、联系方式、办公地址、办理流程（正文）**。附件可选，支持多个 `.xls`、`.xlsx`、`.doc`、`.docx`、`.pdf` 文件，每个最多 20 MB，每份指南最多保留 10 个；修改时可勾选移除旧附件，并上传替代文件。PDF 可在线预览，Word/Excel 以原文件下载，不在服务器上打开、执行或转换。

已发布指南修改后立即生效；撤下后，学生不能再从列表、搜索、原详情或附件地址访问。撤下的指南修改后仍保持撤下，需管理员明确重新发布。附件经过扩展名、大小及基础容器格式校验，并由登录鉴权后的私有入口提供。

原“在办事项”的导航、工作台卡片、页面与新增接口已移除，`/matters/` 系列地址不可用。为保留历史私人咨询及备份，旧数据表和已有咨询关联保留；历史会话仍能按原权限查看和回复，不能再发起新的事项关联咨询。

通知类别使用等宽网格和自动换行；办事指南采用蓝色流程目录，桌面侧栏按类别导航，手机端类别栏可横向滚动。本地样式和脚本地址带修改时间版本号；生产环境改用带内容哈希的静态资源地址，防止旧缓存导致类别挤在一起。更新后执行 `python manage.py migrate`（应用 `0004_serviceguide_guideattachment`）和 `python manage.py collectstatic --noinput`，再重启应用。

## 请销假、实习和租房

导航顺序为：**首页 → 通知汇总 → 办事指南 → 请销假、实习和租房 → 咨询回复 → 月度打卡 → 学生信息汇总（仅管理员）**。申请模块内分为“日常请销假”“实习登记”“校外租房”，学生仅能访问本人记录和附件，管理员可以查看并审核全部申请。

所有新申请的姓名、学号从当前登录账号带入且不可冒名修改，提交时保存身份快照。账号姓名缺失时需先由管理员补全账号资料。日常请假必须填写类型、原因、起止时间、去往省份/直辖市、城市、联系方式，并在以下两项中必选其一（不预选）：**是：导师本人线下签字**；**否：使用电子签名或代签，已征得导师同意**。仍保留待审核撤销、驳回重提和批准后管理员确认销假的原流程。

实习登记填写起止时间、实习单位、实习岗位、实习地址、个人联系方式、紧急联系人和紧急联系方式，并上传实习申请附件。校外租房填写租房原因（科研需求/身体原因/其他）、起止时间、精确到户的详细地址、本人联系方式、紧急联系人及联系方式、是否有校内宿舍，并上传校外租房申请附件。“其他”原因必须说明具体理由，有校内宿舍必须填写宿舍号。租房和实习起止时间必须递增，必填项在后端校验。

两类申请均提示可去**办事指南（业务流程）模块**寻找申请模板，并提供跳转链接。每份申请至少 1 个、最多 10 个附件，每个最多 20 MB，支持 JPG/JPEG/PNG 图片、Word（doc/docx）、Excel（xls/xlsx）和 PDF；进行扩展名、大小和基础文件格式校验。附件仅本人和管理员可经鉴权路由下载，不提供匿名媒体地址。

管理员对待审核的实习/租房申请选择通过或驳回，**驳回原因必填**，审核人、时间和意见写入办理记录，学生可查询。审核采用状态条件更新，重复审核不会覆盖已完成结果。实习/租房支持日期范围、状态和关键词组合查询；本次导出功能用于日常请销假。

升级需执行 `python manage.py migrate`（应用 `0005`、`0006`）、`python manage.py collectstatic --noinput` 后重启。历史请假保留原去向和流程；迁移保存现有账号身份，新增省市和导师签字信息保留为空，在详情/导出中标明历史未填写，不推断或代填导师同意。

## 咨询回复

学生在咨询列表只看到“先查阅通知汇总、办事指南（办事流程）、规章制度和官方问答，未找到答案再咨询”的醒目提示，并可直接跳转查询。点击“发起咨询”后，才提示一次说明问题背景、前因后果、已尝试的处理方式和具体诉求。管理员首次回复前可补充情况；首次回复后，在会话输入区显示“继续追问”提示。后续追问会重新转为待回复，管理员再次回复后变为已回复，全部消息保留；曾有管理员回复的会话在等待下一次回复时仍可继续追问。

官方问答、咨询回复的列表、详情及新增/编辑页面均有当前查看者的平铺身份水印：学生为姓名、学号，管理员为姓名、账号。常规身份的间距为260×140像素，密度约为初版的1.9倍；超长姓名/账号自动扩展以保留完整信息。水印由服务端按登录身份生成，滚动后仍覆盖可视区域，不影响点击和输入，也不写入问答或会话正文。响应使用私有且不缓存设置，原有学生归属和草稿权限继续生效。水印用于截图来源识别，不能完全阻止截图、裁剪或后期去除。

入口位于“请销假、实习和租房”后面，内部为“官方问答”和“咨询回复”。两者共用八类：**日常事务、评奖评优、新生入学、离校手续、党建、后勤及校园管理、教务、其他**，可结合类别与关键词查询。官方问答检索问题及答案；私人咨询可检索主题与消息正文，管理员另可检索学生姓名、学号。

官方问答向所有登录学生公开已发布内容，草稿和撤下内容只有管理员可见。学生发起咨询必须选择类别，咨询正文和多轮回复仅本人及管理员可见；管理员可按待回复/已回复筛选。回复后点击“整理为官方问答”，自动带入咨询类别、主题和管理员答复，学生消息不自动复制；管理员须人工改写、去除个人信息，保存草稿并明确确认发布。公开问答不会展示原始会话或来源链接，原始咨询继续私密。

历史官方问答的已知分类映射到新类别，其余归入“其他”，原分类内部保留以支持回滚；历史未分类咨询归入“其他”，不改动原正文和权限。原 `/faqs/`、`/consultations/` 地址继续可用。

## 请假时间筛选与导出

在“请销假、实习和租房 → 日常请销假”中填写开始日期、结束日期，可与办理状态、姓名/学号/原因关键词组合筛选，也可只填一个日期。日期按北京时间计算，结束日期包含当天。筛选采用**时间交集**：例如筛选 11 月 10–12 日，从 11 月 1 日请到 11 月 30 日的申请也会命中。筛选依据为请假起止时间，不是提交时间。

学生只能筛选本人的记录。管理员点击“导出筛选结果”下载 UTF-8 CSV，支持 Excel 打开；导出使用表单中的当前条件，包含**全部匹配记录，不受分页限制**，不填条件则导出全部。日期非法、前后颠倒或状态不合法时会提示错误，不会忽略条件导出全部数据。

导出字段包括申请编号、学号、姓名、院系/班级、请假类型、起止时间、原因、去向、电话、状态、提交时间、最近审核人/时间/意见、销假确认人/时间/说明和原申请编号，以及去往省份、城市、导师本人线下签字选择。所有时间均为北京时间。CSV 文件保留学号和电话的原始前导零；使用 Excel 导入时将这些列设为文本。公式危险前缀会加单引号作为文字导出。导出请求会写入操作记录。

## 学生信息汇总

原“学生账号”已改名为“学生信息汇总”，仅管理员可见，位于月度打卡下方。原账号创建、批量导入、启用/停用、重置密码等功能保留。必填资料为：**姓名、学号、身份证号、在校状态、所在班级**。所在党支部选填，可留空或填“无”，不影响资料完整性；筛选党支部时可选“未填写”。政治面貌选填：**群众、共青团员、共青团员（入党积极分子）、共青团员（发展对象）、预备党员、正式党员**。院系选填，原“院系/班级”数据保留在该字段。

新增或编辑时须补齐必填资料；在校状态仅有“在校、毕业”，新学生默认在校。身份证号进行 18 位格式及出生日期的基础校验，末位 X 不区分大小写。历史账号新增字段为空时显示“待补全”，不编造证件号、党支部、班级等信息；历史不完整账号仍可单独停用或重置密码。列表和导入预览中的身份证号脱敏显示，完整号码仅在管理员详情/编辑页出现；学生没有本模块的读取或操作权限。

每位学生可添加零条或多条干部履职记录，包含**任职职务、开始日期、结束日期**。结束日期未填写时默认 **2999-12-31**，可手动调整起止日期。“当前履职职务”显示所有满足开始日期≤今天≤结束日期的记录，日期含首尾；未来任职和已结束任职只出现在历史中。旧记录结束日期为空时继续按无明确结束日期处理。详情保留全部历史，每人最多100条。

履职编辑区将职务、开始日期、结束日期和操作按钮排在同一行；窄屏在履职区域内左右滑动。每条记录提供“修改、删除”，修改后显示“保存、取消”。点击保存或删除会再次确认，取消确认不提交；日期错误先提示修改。已有学生的记录逐条即时保存，学生基本资料单独保存，单条操作保留尚未提交的基本资料输入；详情页也提供修改/删除入口。新建学生的履职先逐条确认，随账号一起创建，页面会明确提示当前为待创建资料。

单条履职保存/删除与审计日志在同一事务中完成。每次成功后同步更新编辑版本；若期间学生资料或履职已被其他操作更改，会要求重新加载核对，旧编辑页和旧履职导入预览不能覆盖新变更。正在编辑的履职需先保存或取消，再提交学生基本资料。

筛选采用紧凑搜索卡片：**综合搜索**可搜索姓名、学号、班级、党支部、院系和当前职务，多个关键词用空格分隔，每个词都须匹配（可以分别匹配不同字段）。班级、党支部、政治面貌和当前履职职务使用**下拉多选框**，点击展开后勾选，可搜索选项、清空并查看已选数量，无需按住 Command/Ctrl。单类别多选取并集，不同条件取交集。

在校状态、是否有履职记录、登录状态、资料完整性和当前/已归档范围收在“更多筛选”中，存在已应用条件或输入错误时自动展开。已应用条件以标签显示，可单独移除或清空全部，移除时保留其他条件并回到第一页。选择或修改后点击“查询学生”应用，表格与批量处理使用已应用的筛选范围。当前职务查询匹配任意一条当前有效记录，不匹配已结束或未来任职，分页保留全部条件。

## 学生信息导入模板

管理员在“学生信息汇总 → 导入模板 / 批量导入”下载 UTF-8 CSV，表头依次为：

```text
学号,姓名,身份证号,在校状态,所在党支部,所在班级,政治面貌,院系,初始密码
20260003,张同学,填写本人18位身份证号,在校,无,2026级一班,群众,计算机学院,Initial!Maple2026
```

以上证件号为待替换的说明文字，密码仅为格式示例，须替换为学生的真实资料和正式初始密码。学号和身份证号列请设为文本，保留前导零及末位 X，再另存为 **CSV UTF-8**；此入口不直接接收 `.xlsx`。所在党支部、政治面貌、院系可留空；“在校状态”填写“在校”或“毕业”；“所在班级”填写班级名称，“院系”填写学院或系名称。旧九列模板中的“院系/班级”兼容识别为院系，不会作为所在班级导入。干部履职历史可在学生编辑页逐条维护，也可通过Excel导入。

导入方式分为：

- **新增学生账号及资料**：学号必须尚未存在；初始密码为 10–128 字符并符合强度规则，管理员账号不可导入。已有账号不会被覆盖，出现错误或预览后学号冲突时整批拒绝。
- **补充/更新已有学生资料**：学号必须精确匹配已有学生，CSV 只需保留“学号”和至少一项待修改资料列，顺序不限；初始密码列可删除，保留时必须留空。只更新保留的资料列，未包含的列保持原值；选填列留空表示清空该项，必填列不能留空。仅更新基本资料，**不修改学号、密码、权限、登录/归档状态、干部履职和已有业务记录**。可用于给约 1500 名现有学生批量补全新增字段，也可只更新政治面貌等单项资料；未涉及的历史缺失字段不强制补齐，归档学生也可补全。预览后基本资料或学号变化、账号删除或转为管理员时整批拒绝。

只更新政治面貌的操作：进入“学生信息汇总 → 批量导入”，点击“下载政治面貌更新模板”，填写两列后另存为 CSV UTF-8，选择“补充 / 更新已有学生资料”，上传并核对预览中标明的更新列，最后确认整批更新。例如：

```csv
学号,政治面貌
20260003,共青团员（入党积极分子）
20260004,预备党员
```

政治面貌应填写上述六种中文名称之一；学生学号列使用文本格式，不附加 Excel 公式。若还需要批量更新党支部，可加一列“所在党支部”；不需要修改姓名、班级等资料时，不要保留这些列。预览显示其他现有资料供核对，实际只修改提示的列。此入口不导入干部履职历史。

每次最多 **2000 人、5 MB**；两种方式均先校验再预览，**每页 100 人，确认处理整个批次**。新增校验全部必填项，更新校验 CSV 中选定字段；包括姓名学号、证件号基础格式、在校状态、类别、文件内重复等，有错误整批不写入，最多显示前 30 条错误。仅上传管理员可访问和确认预览，一天后失效；取消不改动学生，重复确认不重复处理。原始 CSV 不保存，预览不展示密码，确认后清空暂存资料。旧四列模板、含毕业年月的旧九列模板及旧版未确认预览不能继续使用，须重新下载模板；普通学生资料导入预览版本为3。

新增模式采用一次整批查重、最多两个线程分别加盐计算密码、事务内分批插入；更新模式无需密码哈希，事务内只批量更新资料字段。部署保留 Nginx 账号上传等待 600 秒、Gunicorn gthread 和平滑退出 600 秒、systemd SIGTERM / 620 秒的配置。

## Excel毕业名单与履职信息导入

在“学生信息汇总”点击 **批量修改毕业学生**，下载Excel模板并填写“学号、姓名”。校验并预览后确认整批处理，仅将在校学生改为毕业，已毕业学生无需重复修改。毕业分类不自动停用登录，不归档、不删除业务历史。

点击 **导入履职信息**，模板为“学号、姓名、任职职务、开始日期、结束日期”。日期使用 `YYYY-MM-DD`，也支持Excel日期单元格；结束日期可留空，预览时填为 `2999-12-31`。同一学生、同一职务、同一开始日期的记录更新结束日期，其余新增历史；同一文件重复上述组合会整批拒绝。可为一名学生填写多条不同职务，符合当天任职时间的记录全部显示为当前职务，修改日期后即时重新计算。

两个入口均支持 `.xlsx` 和 `.xls`，每批最多2000行、5 MB，模板含单独填写说明页。学号建议使用文本以保留前导零，姓名须与现有学生账号精确匹配；不接受管理员账号，不自动新增学生。名单第一行保留表头，只保留一张数据工作表（可保留“填写说明”）；文件仅在内存中解析，预览按100条分页，确认处理全部分页。任一行无效整批不修改；预览归上传管理员所有，一天后过期，可取消，重复确认不重复写入。预览后目标基本资料发生变化会整批拒绝；履职批次还核对历史和账号状态。旧编辑页也能检测Excel导入造成的资料冲突。

升级前备份并安装更新后的依赖，应用 `0010` 迁移，收集静态资源并重启。按已确认规则，**现有学生初始统一为在校**，后续用名单确认毕业；原毕业年月保存在不可编辑的历史字段，不根据旧日期自动判定毕业。密码、权限、启停/归档状态、原履职及业务记录保留。旧结束日期空值保持原值，新增和导入结束日期默认2999-12-31。

## 筛选后单个或批量删除学生

可在详情选择删除，或在列表勾选学生、选择“当前筛选结果的全部当前学生（跨分页）”，进入**名单核对页面**，查看预计彻底删除/归档人数及每人的处理方式。核对后必须勾选确认才能执行，也可以取消；核对结果仅当前管理员会话可访问，30 分钟过期，确认后失效，不能重放。新加入的筛选匹配学生不会自动加入已核对名单。

按已确认规则：**无业务关联记录的学生彻底删除；有请假、实习、租房、咨询、打卡、干部履职或其他受保护记录的学生归档并停用**。归档保留所有历史，默认列表不再展示；通过“已归档学生”查询，可恢复到列表，恢复后登录仍停用，需核对后单独启用。停用/归档会使旧登录会话持续失效，之后启用也需重新登录；密码保留。

不能删除管理员、超管、已归档学生，不能把筛选范围外的学生塞入名单。核对后若身份或名单变化，会要求重新选择；若新产生业务关联则改为归档保留。批量处理和操作日志在同一事务内完成，失败不会部分删除。

升级须先备份，然后执行 `python manage.py migrate`（应用 `0008`）、`python manage.py collectstatic --noinput` 并重启应用。迁移不会修改现有学生的姓名、学号、原密码、启停状态和业务历史。

## 月度打卡与导入模板

入口紧接“咨询回复”下方。每名学生每月显示一条记录：**学号、姓名、月份、打卡天数、请假天数、总天数**，不显示每日明细。管理员可按**起始年月至结束年月**、学生姓名或学号组合查询，支持跨年，包含起止两个月；任一端留空表示该端不限，两端留空查询全部已导入月份，首次进入默认当前月。还可选择**打卡天数、请假天数或总天数**，填写最少/最多天数（0–31的整数），范围包含首尾，任一端留空表示不限。天数按每条月度记录判断，不将区间内多个月份累计后筛选；例如查2026-09至2026-12、打卡20–25天，返回各月符合条件的记录。学生仅查询本人，可按年份/月筛选，月份选择“全年”可查看所选年各月的记录。未导入月份显示无记录，不自动填零。

**总天数＝打卡天数＋请假天数**，两项都为非负整数；按已确认规则不支持半天。总天数来自导入数据，不从请假申请自动推算，也不要求必须等于自然月天数，但不能超过该月实际天数。列表顶部统计对应当前筛选条件下的全部匹配记录，包含分页以外的结果。

表格六列（学号、姓名、月份、打卡天数、请假天数、总天数）均提供上下三角按钮：上三角升序、下三角降序，当前方向高亮。排序由数据库在分页前执行，天数按数值、月份按年月排序，姓名和学号按数据库文本顺序；同值按月份倒序、学号及记录编号稳定排列。切换排序保留已应用的筛选条件并回到第一页，翻页和重新查询保留排序；顶部合计与匹配学生人数覆盖整个筛选结果，不仅当前页。非法范围、天数类别或排序条件会显示错误并返回空列表。旧year/month及YYYY-MM单月链接仍兼容。

管理员可直接点击列表页“下载导入模板”，或进入“导入月度记录”下载。UTF-8 CSV 表头必须依次为：

```text
学号,姓名,月份,打卡记录,请假天数
20260001,张同学,2026-11,20,2
20260002,李同学,2026-11,21,1
```

以上姓名为格式示例，正式导入时须与对应学生账号姓名一致。“打卡记录”填写当月打卡天数，不填写文字或每日状态；月份严格使用 `YYYY-MM`（例如 `2026-11`），年份不早于 1900。学号列设为文本以保留前导零；请先创建学生账号，停用账号和管理员账号不可导入。

每次最多 **5000 条、2 MB**，可混合多个月份和年份。同一文件不能有重复学号/月，姓名不匹配、缺失列、非法月份、负数/小数、天数之和超出该月上限等都会整批拒绝。成功后先预览，**每页 100 条，确认导入整个批次**；同一学生同一月份再次导入会替换该月汇总，其他学生和月份保留。仅上传管理员可访问及确认预览，预览一天后过期；确认后清空暂存数据，重复确认不会重复创建。预览后账号或姓名变更会要求重新上传。

升级时执行 `python manage.py migrate`（应用 `0007`）和 `python manage.py collectstatic --noinput`，再重启应用。旧每日数据按人/月汇总：正常和迟到计入打卡天数，已标记“请假”的记录计入请假天数，缺卡不计入两项；原始每日表和备注完整保留，但不再展示或接受旧每日 CSV。旧版未确认预览须取消后改用月度模板上传。新月度导入后，该月显示值以新导入的汇总为准。降级无法将新月度汇总还原成每日明细，需要升级前备份配合恢复。

## 验证与维护

本地已准备 **1500 名学生、36615 条月度打卡及各模块分类/状态/附件测试数据**。管理员 `qa_admin`、学生 `qa000001`，初始密码均为 `QaTest!2026`；原有账号与业务保留。账号场景、导入文件包、生成/清理方法详见 [测试数据使用说明](docs/TEST_DATA_GUIDE.md)。

学生信息表支持拖动表头分隔线调整列宽，浏览器记住设置，可一键恢复默认；长内容单行省略，悬停或进入详情查看。列表身份证仍脱敏。所有业务分页支持页码输入跳转、相邻页和首尾页选择，以及每页条数下拉选择（10、12、20、50、100条，另可选择“自定义”填写1–100条）。各模块分别记住本次会话的条数，调整条数回到第一页；翻页保留筛选和排序，导入确认及筛选导出仍处理完整批次/结果。履职历史也支持分页。查询框、选择框和查询按钮统一高度，并调整窄屏换行与长姓名显示。

```sh
python manage.py test portal
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py backup_data
python manage.py cleanup_data
```

真实 HTTP 回归检查（使用独立临时数据库，结束后自动清理，不修改当前账号和业务记录）：

```sh
.venv/bin/python scripts/smoke_http.py --skip-capacity
```

去掉 `--skip-capacity` 默认同时测试 1500 人导入及密码哈希耗时；用 `--capacity-rows 2000` 可测试最大批次，用 `--gunicorn` 可通过部署配置中的 Gunicorn 运行。这是本地功能与耗时检查，不是生产并发压测。

备份默认写入 `backups/`，含数据库快照及 `media/` 文件，文件权限为仅当前用户可读。生产环境需要 `pg_dump`。备份应同步到另一台主机或可靠存储，并制定保留周期；命令不会自动删除历史备份。

生产部署步骤见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。业务实现见 `portal/`，界面在 `templates/` 与 `static/`；原始需求文档保持不变。
